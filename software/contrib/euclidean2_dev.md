# EuroPi 6通道双欧几里得音序器 实现规范
# 适配128*32显示屏 | 6路独立CV输出 | 无Shift时序偏移

〇、实现架构（重构后单文件，参照 europi-ws/ARCHITECTURE.md）
================================================================
euclidean2.py 现为**单文件**，但内部严格按 ARCHITECTURE.md 的分层原则组织，各层只通过
「语义事件 / 命令 / 模型读取」交互，且 Sequencer / Pattern / Track / Transport 中**不出现任何
EuroPi API 调用**（换平台只需重写 Hardware 适配器）。模块映射如下：

- Hardware Adapter  → `Hardware`：唯一访问 oled/k1/k2/b1/b2/cv*/din 的模块（硬件抽象）。
- Input Manager    → `InputManager`：硬件状态 → 语义事件 `KnobTurn` / `ButtonEvent`（不改状态）。
- 语义事件         → `KnobTurn`、`ButtonEvent`（含 `__slots__` 复用单例，避免每轮分配）。
- Controller       → `Euclidean2`：事件分发 `dispatch()` + 命令派发 + 触发渲染（几乎无业务）。
- UI Pages         → `Euclidean2._on_knob1/_on_knob2/_edit_global/_edit_channel/_apply_pickup`：
                     把交互译为命令，只调用 `Transport` / `Track` 的设置器。
- ApplicationState → `AppState`：仅 UI 状态（page / sel / k2 拾取 / dirty）。
- Sequencer Core：
    * `EuclidPattern`：Pattern（单个发生器的音乐内容 steps/pulses/rot/prob + pattern[]，不含播放头）。
    * `Track`：TrackSettings(merge) + TrackPlayer(g1_pos/g2_pos 播放头 + out_reg 移位寄存器)。
      即一个通道 = 双 Pattern + TrackSettings + TrackPlayer。输出电压为全局项，见 `Transport.level`。
    * `Sequencer`：接收 ClockTick → 分发给各 `Track.output()` → 经 Hardware 输出 CV/Gate。
- Transport        → `Transport`：全局时间（BPM / 倍率 mul / 输出电压 level / 时钟源 INT|EXT / 运行状态），实际时钟 = BPM×mul，INT 用内部 Timer，
                      EXT 由 din 上升沿经 `ext_tick` 驱动。
- Renderer         → `Renderer`：无状态，每次 `render(app, seq, transport, hw)` 读模型并经 Hardware 绘制，
                      不修改、不持有持久 UI 数据。

数据流：硬件 → Hardware → InputManager(事件) → Controller →
        [UI Pages 命令 → Transport/Track]  /  [ClockTick → Sequencer → 输出事件 → Hardware]；
        渲染在 `app.dirty` 时由 Controller 调用 `Renderer.render()`。

状态持久化仍由 `SAVE_STATES` 常量控制（默认 False，完全屏蔽写盘/加载）；开启后行为同下文章节 9.8。
以下「一、…九、」规范的所有音乐/UI 行为在重构后保持不变。

一、硬件定义
1. 输出：6路独立CV/GATE输出，每一路绑定一组独立双欧几里得发生器(Gen1+Gen2)，通道间完全独立互不影响
2. 按键：B1、B2 为页面切换按键，循环切换编辑页面
3. 旋钮：K1 参数选择旋钮(跳转策略)，K2 参数数值调节旋钮(拾取跟随策略)
4. 屏幕：分辨率128×32单色屏
5. 时钟系统：支持内部时钟、外部时钟双模式，内部时钟可自定义BPM与时钟倍率mul

二、页面切换顺序
全局时钟页(编号0) → CH1编辑页 → CH2编辑页 → CH3编辑页 → CH4编辑页 → CH5编辑页 → CH6编辑页 → 循环

三、全局时钟页功能
1. 参数1：时钟源选择（内部时钟 / 外部时钟）
2. 参数2：内部时钟BPM数值调节（20–240）
3. 参数3：时钟倍率mul数值调节（1–16），实际时钟 = BPM × mul（默认BPM=120, mul=4 → 480）
4. 全局时钟统一驱动全部6路音序运行时序

四、单通道可编辑全部参数（K1遍历列表），显示时要使用缩写
-  Gen1 Rotate 相位旋转值
-  Gen2 Rotate 相位旋转值
-  Gen1 Steps 序列总步数
-  Gen2 Steps 序列总步数
-  Gen1 Pulses 脉冲触发数
-  Gen2 Pulses 脉冲触发数
-  Gen1 Prob 触发保留概率
-  Gen2 Prob 触发保留概率
-  双序列合并逻辑模式

（输出电压为全局设置项，于全局时钟页调节，不在此通道参数列表中。）

五、旋钮交互规则
1. K1 跳转策略：旋转直接顺序跳转选中参数，无缓冲无过渡，参数索引随旋钮档位即时变化；
   为防 ADC 噪声误跳，仍加 ±0.5 档迟滞（仅超过下一档阈值中点才切换，详见 9.3 / 9.17）。
2. K2 拾取策略：旋钮物理位置数值与当前选中参数值不一致时，转动无效果；旋钮数值匹配参数值后，转动才可修改参数大小

六、128*32屏幕UI布局规则
1. 顶部单行状态栏：固定格式 当前页面编号 （空格）当前参数名 （空格）当前参数数值
2. 中下两行序列显示区：第一行显示Gen1原始序列，第二行显示Gen2原始序列
3. 序列图形标识：触发步进绘制实心矩形，空步步进绘制空心矩形
4. 可视上限16步，超出长度支持横向滚动浏览完整序列
5. 界面仅展示两路原生生成序列，不展示对齐合并后序列

七、欧几里得核心运算逻辑
1. 单发生器固定执行流程：Björklund算法生成序列 → 相位旋转偏移。
   注意：概率不影响存储序列，仅作为触发时刻的保留判定（见 4./9.9），故生成流程不含概率过滤。
2. 双序列各自独立维护：Gen1、Gen2 分别保存自身 pattern 与播放头，不做 LCM 预对齐；
   每步以各自 position（对各自 steps 取模）查表，两路天然按各自周期运行，无需统一循环周期数组
3. 合并运算模式：OR、AND、XOR、仅Gen1输出、仅Gen2输出五种模式（对齐 Digitakt 2 双机器）
4. 合并在“触发时刻”实时运算：取 g1.pattern[g1.position] 与 g2.pattern[g2.position]
   按模式做逻辑运算并叠加各自概率判定，得到该步 ON/OFF，再转换为 GATE(通道CV电平) 信号输出

八、数值范围约束
1. 序列步数范围：4~64
2. 脉冲数量范围：0~当前通道对应发生器总步数
3. 旋转值范围：0~对应发生器总步数
4. 概率数值范围：0~100

九、硬件特性评估与细节补充（基于 europi_hardware.py / europi.py 实机定义）
================================================================

9.1 实机资源核对（决定可行性）
----------------------------------------------------------------
- 输出：cv1..cv6 共 6 路（NUM_CVS=6，europi_hardware.py:79），每路为单个 Output 对象
  （europi_hardware.py:474-560），CV 与 GATE 共用同一物理插孔：
  * .voltage(v)  设定连续电压（0~10V，受校准）
  * .on()/.off() 以 gate_voltage（默认 5V）做高/低门
  => 结论：一个通道只有“一个插孔”，因此双发生器“合并逻辑”的输出只能落在该单通道上，
     不能在同一通道既输出 GATE 又输出独立 CV。必须采用下述解释（见 9.4）。
- 按键：b1(PIN_B1=4)、b2(PIN_B2=5)，均带 200ms 去抖（DigitalReader/Button）。
- 旋钮：k1(PIN_K1=27)、k2(PIN_K2=28)，均为 12-bit ADC 读取，read_position 默认 100 档，
  默认 256 次采样；超过 4096 档会失去分辨率（europi_hardware.py:289-308 注释）。
- 外部时钟：din(PIN_DIN=22)，上升沿 >0.8V 判定 HIGH（DigitalInput）。
- 模拟输入：ain(PIN_AIN=26)，本设计未使用，可作后续扩展（如通道电平由外部 CV 调制）。
- 屏幕：oled 默认 DISPLAY_WIDTH=128 / DISPLAY_HEIGHT=32（europi.py:54-56），
  默认 8×8 等宽字体 => 单行最多 16 字符、整屏 4 行（europi.py:58-60）。

9.2 逐项合理性评估
----------------------------------------------------------------
- 一/二（6 路独立双发生器 + 页面顺序）：可行。每通道绑定 (Gen1,Gen2) 各一组参数，
  合并后写入 cv[x]，通道间互不影响，与硬件 6 路输出一一对应。
- 三（全局时钟页）：可行。外部时钟用 din.handler 上升沿驱动；内部时钟用
  machine.Timer 周期回调驱动（周期 = 60000/(BPM×mul) ms）。
- 四（单通道 9 项参数）：可行，但 K1 直接映射到 9 档需在代码内用 k1.read_position(9)。
- 五（K1 跳转 / K2 拾取）：可行，但“无缓冲直接切换”与“拾取匹配”二处需补充判定细则（见 9.3）。
- 六（128×32 UI）：方向正确，但格式需压缩（见 9.5），且 16 步可视 + 横向滚动需补充滚动触发方式。
- 七（Björklund→旋转→概率→对齐→合并）：完全可行，算法与现有 euclid.py 一致可复用。
- 八（数值范围）：可行；Steps 上限 128 比现有 euclid 的 32 更重，但仍可接受（每通道 2 序列
  共 1536 步内存开销极小），建议实机压测长序列下 Timer 抖动。

9.3 旋钮交互细则（必须补充，否则无法落地）
----------------------------------------------------------------
- K1 跳转策略：
  * 用 k1.read_position(10) 映射到当前页的 10 个参数索引（0..9）。
  * “无缓冲”即参数索引 = 旋钮档位，转动即刻切换；为避免噪声导致误跳，建议对 K1 读数加
    ±0.5 档迟滞（仅当超过下一档阈值中点才切换）。
  * 进入新页面时 K1 物理位置即决定初始选中项，符合“直接跳转”语义。
- K2 拾取策略（pickup）：
  * 定义拾取容差 TOL（建议 = max(2, 量程/32)）：当 | k2.percent()*量程 - 当前值 | <= TOL 时
    视为“已抓取”，之后旋钮增量才施加到参数。
  * 抓取前转动 K2 无效（不修改值，仅可在状态栏显示“抓取中…”提示）。
  * 离散参数（合并模式 5 选 1、时钟源 2 选 1）同样适用：需旋钮档位落入对应槽位 ±TOL 才抓取。
  * 切换参数项（K1）或切换页面后，K2 抓取状态重置，需重新拾取——符合规范描述。
  * 数值提交消抖：抓取后，旋钮目标值需在 K2_DEBOUNCE_MS(=40ms) 窗口内保持稳定（无跳变）才真正
    写入参数并触发 rebuild/regenerate，避免 ADC 噪声在相邻整数档间抖动造成误触发；目标值一旦变化
    即重启计时窗口。

9.4 通道输出语义澄清（关键硬件约束）
----------------------------------------------------------------
- “双序列合并逻辑模式”的结果仅决定该步骤 ON/OFF。
- 合并语义对齐 Elektron Digitakt 2 的“双机器(Dual Machine)”：Gen1、Gen2 是两个独立
  发生器，各自有 steps/pulses/rot/prob；二者在每一步通过合并逻辑(OR/AND/XOR/GEN1/GEN2)
  实时得到该通道最终输出。GEN1/GEN2 模式即只取其中一路，等效旁路合并。
- 该通道唯一插孔在 ON 时输出“全局输出电压”，OFF 时输出 0V。
  实现：ON → cv[x].voltage(全局电平)；OFF → cv[x].off()。
  即“全局输出电压”本质是自定义门高电压（替代默认 5V gate），取值范围 0~10V，默认 5V，
  由全局时钟页统一设置，作用于全部 6 路。
- 因此本模块每通道 = 一个受合并逻辑调制的门，门高电平可调；不提供第二个独立 CV 输出。
- 建议文档明确：若用户需要“门 + 独立音高 CV”双信号，需占用两个通道（CHn.Gen 作门、
  另一通道设为常量电平），本规范不内置该模式。

9.5 128×32 UI 布局细化（必须压缩，否则超宽）
----------------------------------------------------------------
- 整屏 4 行（y=0/8/16/24），8×8 字。
- 行0 状态栏（≤16 字符）：采用紧凑格式
  `P{page} {参数缩写}:{值}`（去掉 C{ch}；合并模式仅在 K1 选中 MERG 参数时显示于行0）
  例：`P3 ROT1:5` / `P0 CLK INT` / `P0 BPM:120` / `P0 MUL:4`
  参数名缩写表（统一 4 字符，可读性优先；顺序即 K1 遍历顺序，按发生器分组）：
  ROT1=Gen1 Rotate, PLS1=Gen1 Pulses, STP1=Gen1 Steps, ROT2=Gen2 Rotate,
  PLS2=Gen2 Pulses, STP2=Gen2 Steps, PRB1=Gen1 Prob, PRB2=Gen2 Prob,
  MERG=合并模式（输出电压为全局项，缩写 LVL 仅用于全局时钟页）。
- 全局时钟页（P0）**只绘制行0 顶栏**，其余三行留空（不显示 CLK:/BPM:/提示行）。
- 行1 显示 Gen1 原始序列（实心块=触发，2×2 点=空步）。
- 行2 显示 Gen2 原始序列。
- 行3 显示**移位寄存器式输出序列**（ch.out_reg，实心块=触发，2×2 点=空步），
  长度 = min(16, 最短序列)，随播放头左移滚动（左出右补）。
- 步进图形：每步占 8px 宽，16 步正好 128px；触发用 oled.fill_rect 画实心块，
  空步用 oled.fill_rect 画 2×2 点；不画播放头下划线标记。
- 横向滚动（移位寄存器式，所有长度统一）：每行将“当前步”固定显示在该行最左一格(col 0)，
  播放头推进时整窗向左滚动——左侧步移出、右侧以各自序列长度取模补位（循环显示）。
  显示格数 = min(16, Steps)：序列步数 < 16 时只显示实际步数（不补满 16 格），>= 16 时显示 16 格；
  即显示步 idx = (当前步 + i) % Steps，i = 0..min(16, Steps)-1。
  例：Steps=8、当前步=5 → 显示 8 格 5,6,7,0,1,2,3,4（循环，不补白）；
  Steps=24、当前步=5 → 显示 16 格 5..20；推进到 6 时显示 6..21。
- 因两序列分别维护且步长可不同，Gen1 行、Gen2 行、输出序列行各自按自身播放头/最短长度独立滚动，行为一致。
- 切换页面时先 `oled.fill(0); oled.show()` 清空整屏再重绘，避免残影。
- 无需长按/手动滚动模式；滚动完全由播放头位置事件驱动（见 9.10），不占用 K2。

9.6 全局时钟页布局与数值补充
----------------------------------------------------------------
- 内部 BPM 范围建议 20~240，默认 120；时钟倍率 mul 范围 1~16，默认 4；实际时钟 = BPM × mul。
  外部时钟时 BPM/mul 项置灰/显示“EXT”。
- 全局时钟页 3 项参数：参数1 时钟源(INT/EXT，K2 拾取切换)、参数2 BPM、参数3 倍率 mul。
- 门长统一为 GATE_MS=5ms：无论 INT/EXT/手动触发，均在置位输出后用 one-shot Timer(5ms)
  统一拉低所有 CV（turn_off_all_cvs），不再随周期变化，也不再由外部下降沿关闭门。
- 内部时钟与外部时钟、手动触发共用同一置位+定时拉低逻辑（见 9.13），保证门宽一致。

9.7 页面切换方向补充
----------------------------------------------------------------
- B1 = 上一页（Prev），B2 = 下一页（Next），循环回到全局时钟页。
- 长按 B2（>500ms）快捷回到全局时钟页（第 0 页），便于快速改 BPM。

9.8 状态持久化（规范未提及，建议补充）
----------------------------------------------------------------
- 每通道 steps/pulses/rot/prob/merge 及全局时钟源/BPM/倍率 mul/输出电压 应保存到本模块 state 文件
  （如 euclidean2.json），启动 main() 时加载，避免断电丢失。可复用 EuroPiScript 的
  _state_filename 机制或自行 JSON 存取。

9.9 性能与边界注意
----------------------------------------------------------------
- 双序列分别独立维护：Gen1、Gen2 各自保存 `pattern[]`（Björklund 生成 + 旋转后的 0/1 数组，
  **不含概率信息**）与 `position`。不预生成 LCM 全数组；合并在“触发时刻”才计算：
  读取 g1.pattern[g1.position] 与 g2.pattern[g2.position]，按合并模式做 OR/AND/XOR/选路，
  再叠加各自概率判定，得到该通道本步 ON/OFF。避免 steps=128 互质时 LCM 达上万的内存/计算浪费。
- regenerate 不重置播放头（非必要不重置）：重建 pattern 后保留原 `position`，
  仅当新 steps <= position 时对 position 取模回绕，保证实时调参时听感连续。
- 所有序列仅在参数变更（steps/pulses/rot/prob/merge 改变）时 regenerate()，
  运行时循环/触发回调只做“查表 + 一步逻辑运算 + 一次概率随机”，开销极低。
- 概率语义明确：“触发保留概率 Prob%”= 该步本应触发时，以 Prob/100 概率保持触发，
  否则按空步处理（与现有 euclid skip 相反，文档需写明）。

9.10 事件驱动架构（避免不必要计算）
----------------------------------------------------------------
- 时钟驱动走事件而非轮询：
  * 外部时钟：din.handler(上升沿) 触发 6 通道同步 advance（置位输出，并由 one-shot Timer 5ms 后拉低）。
  * 内部时钟：machine.Timer 周期回调中 advance（周期 = 60000/(BPM×mul) ms），
    同样置位输出并由复用的 one-shot Timer 在 GATE_MS=5ms 后统一拉低所有门，不阻塞主循环。
  * 已移除 din.handler_falling：外部门宽统一为 5ms，与外部输入宽度无关。
- 旋钮不空转计算：K1 选中参数仅在“档位跨越阈值”时切换参数项；K2 仅在已拾取后，
  其增量才施加到当前参数并触发一次 regenerate()，未拾取时忽略，不产生重算。
- 屏幕仅在“脏”时重绘：维护 viz_dirty / ui_dirty 标志，播放头推进或参数变更置脏，
  主循环仅在脏时 oled.fill+draw+show；空闲不刷屏（同时利于屏保/省电）。
- 主循环职责收敛为：处理 UI 脏重绘 + 状态持久化检查；所有时序与数值变更均由事件回调完成。
- 触发回调(advance)内保持最小工作量：仅更新 position、计算合并、置门/电平、置脏，
  不在此做序列重建或字符串拼接（字符串/图形在重绘阶段做）。

9.11 手动触发（无时钟时调试用）
----------------------------------------------------------------
- B1/B2 已被页面切换占用，外部无时钟时无法试听。新增：长按 B1（按下持续时间 >500ms）
  触发一次手动 advance（等效一次时钟上升沿），便于无外部时钟时调试/试听；短按 B1 仍为上一页。
- 与 9.7 的长按 B2 回主页共存：B1=长按手动触发，B2=长按回主页，互不冲突。

9.12 模块定位边界（明确范围）
----------------------------------------------------------------
- 本模块是节奏 / GATE 音序器，不是音高 / CV 音序器：每通道单插孔、合并只决定 ON/OFF，
  “全局输出电压”即门高电压（0~10V，默认 5V），于全局时钟页统一设置。如需每步输出音高，需另做量化映射，不在本规范。

9.13 内部时钟 Timer 资源（避免泄漏）
----------------------------------------------------------------
- 内部时钟用一个周期性 machine.Timer 驱动 tick；门关闭用“同一个”复用的 one-shot Timer，
  每次 tick 调用其 .init() 重新触发（周期 = GATE_MS=5ms），禁止每个 tick 新建 Timer 对象造成泄漏。
- 门长统一 = 5ms：无论 INT/EXT/手动触发，均在置位输出后由该复用的 one-shot Timer 回调统一拉低所有门；
  内部周期触发也会调度该 5ms 拉低（此前仅在 _fire 中调度，INT 周期回调未关门，已修复）。

9.14 时钟源切换启停
----------------------------------------------------------------
- 全局时钟页切换“时钟源(INT/EXT)”时即时生效：选 INT → 启动周期 Timer；选 EXT → 停止 Timer
  并改由 din.handler 驱动。切换瞬间不丢拍：保留各通道 position，仅更换驱动源。
- BPM/倍率 mul 在 EXT 模式下也可由 K2 预调（值被保存，切回 INT 后立即生效）。

9.15 长按检测机制
----------------------------------------------------------------
- 按钮硬件仅支持短按去抖，无长按 API。长按（B1 手动触发 / B2 回主页）由主循环记录
  b1/b2.last_pressed() 的 ticks_ms，在循环中判断按下持续时间 >=500ms 触发一次，并置标志防重复触发。

9.16 合并模式与概率叠加顺序
----------------------------------------------------------------
- OR / AND / XOR：Gen1、Gen2 各自先按自身 Prob 做保留判定，再对两路结果做逻辑运算。
- GEN1 / GEN2：仅取被选那一路，并仅应用该路 Prob；另一路完全旁路，不参与运算也不消耗随机数。

9.17 其余小项
----------------------------------------------------------------
- 五.1 已补：K1“无缓冲”指索引随档位即时变化，但仍加 ±0.5 档迟滞防 ADC 噪声误跳。
- menu 入口显示名 ≤16 字符，建议 "Euclid2 6ch"（类名 Euclidean2，继承 EuroPiScript）。
- 状态持久化为自定义实现（非 SettingsMenu 框架），因本模块旋钮交互为自定义 K1/K2 逻辑（见 9.8）。
- 标题“无Shift时序偏移”指通道间无独立时钟分频 / 延迟（全部共享全局时钟统一驱动）；
  各通道内 Gen1/Gen2 因步长不同而产生的相对漂移属预期行为，不属于“Shift 偏移”。
